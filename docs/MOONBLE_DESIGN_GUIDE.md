# Moonble 디자인 가이드와 화면별 반영 계획

현행 기준일: 2026-10-29

모바일 시각 기준은 [Moonble 포켓폴리오](https://moonble.com/pocketfolio/)다. 아래 공통 표와 2026-10-24·2026-10-29 기준을 우선 적용한다. 날짜별 과거 기록은 당시의 변경 이력이며 현행 규격을 덮어쓰지 않는다.

## 디자인 방향

Moonble의 화면을 흰색 바탕, 옅은 회색 보조 영역, 명확한 파란색 행동 버튼으로 통일한다. 토스 스타일에서 읽기 쉬운 글자 계층, 충분한 여백, 한 영역에 하나의 주요 행동이라는 원칙을 참고한다. 아래 수치는 Moonble에 적용하기 위해 정한 기준이며 토스의 공식 규격을 뜻하지 않는다.

문제지 목록은 제공된 Figma 홈 캡처의 정보 구조를 참고한다. 왼쪽 탐색, 상단 검색과 필터, 넓은 문서 미리보기, 아래쪽 제목과 설명을 사용한다. 문제지를 선택하면 기존 문제 풀이로 진입한다. 미리보기는 실제 제공되는 문제의 내용으로 구성하고, 임의의 완료율·사용자 수·최근 수정 시각을 표시하지 않는다.

공통 값은 `src/design-system.css`의 `--mb-*` 변수를 단일 기준으로 사용한다. 화면별 CSS에서 같은 역할의 값을 새로 만들지 않는다. 모바일 조정은 현재의 DOM 순서, 콘텐츠 폭, 카드 배치, 목록 전환과 동작을 유지하면서 글자 계층·색상·여백을 맞추는 범위로 한다.

## 웹폰트

- 사용자에게 보이는 한글·영문 UI와 텍스트 기반 Moonble 로고는 **Pretendard**로 통일한다.
- 텍스트 로고는 800을 사용하고, 일반 UI 굵기는 400(본문), 500(메뉴·일반 라벨), 600(폼 라벨·카드 제목·버튼), 700(페이지·모바일 영역·대화상자 제목)으로 제한한다.
- [Pretendard 공식 웹폰트 안내](https://github.com/orioncactus/pretendard#웹폰트)의 v1.3.9 다이나믹 서브셋을 사용한다. CDN 장애나 로딩 전에는 시스템 글꼴로 본문을 먼저 표시한다.
- 웹폰트 선언만으로 적용 완료를 판단하지 않는다. 대표 한글 문장이 있는 각 화면에서 실제 폰트 로딩과 계산된 `font-family`를 확인한다.
- 폼 컨트롤, SVG의 `text`, 기존 인라인 스타일에도 다른 폰트가 남아 있는지 확인한다. 코드 표시처럼 문법 구분에 고정폭이 필요한 콘텐츠는 별도로 취급한다.

```css
@import url('https://cdn.jsdelivr.net/gh/orioncactus/pretendard@v1.3.9/dist/web/static/pretendard-dynamic-subset.min.css');
font-family: var(--mb-font-sans);
```

## 글자 크기와 계층

표의 px 값은 브라우저 기본 글자 크기가 16px일 때의 기준이다. 구현은 rem을 사용해 사용자의 글자 확대 설정을 따른다.

| 역할 | 데스크톱 크기 / 행간 | 모바일 크기 / 행간 | 굵기 | 적용 위치 |
| --- | --- | --- | --- | --- |
| 특별한 소개 제목 | 32 / 40 | 28 / 36 | 700 | 소개 영역에 한정 |
| 페이지 제목 | 28 / 36 | 24 / 32 | 700 | 로그인, 회원가입, 프로필, PRD, 문제지 목록 |
| 영역 제목 | 22 / 30 | 17 / 24 | 데스크톱 600, 모바일 700 | 주요 섹션, 문제 생성 단계 제목 |
| 카드 제목 | 18 / 26 | 문제지 14 / 20, PRD 16 / 24 | 600 | 기존 카드 밀도와 두 열 배치 유지 |
| 대화상자·빈 상태 제목 | 18 / 26 | 18 / 26 | 700 | 대화상자, 바텀시트, 검색 결과 없음 |
| 본문·입력 | 16 / 24 | 16 / 24 | 400 | 입력값, 주요 본문 |
| 주요 폼·시트 버튼 | 16 / 24 | 16 / 24 | 600 | 로그인, 저장, 생성, 확인 |
| 메뉴·라벨 | 14 / 20 | 14 / 20 | 메뉴·라벨 500, 폼 라벨 600 | 헤더 메뉴, 필드명 |
| 설명 | 14 / 20 | 13 / 20 | 400 | 페이지·영역 안내와 카드 설명 |
| 보조 정보 | 12 / 18 | 12 / 18 | 400 또는 500 | 문항 수, 상태, 날짜 |
| 문제 지문·긴 문서 | 16 / 28 | 16 / 28 | 지문 600, 문서 400 | 지문과 PRD 미리보기 본문 |

사용자에게 읽도록 제공하는 일반 텍스트와 캡션은 최소 12px을 사용한다. 기존 모바일 독바는 380px 이하에서만 11px 라벨을 유지하고, 항목의 터치 높이는 64px을 유지한다. 문제지 썸네일 안의 축소 문서는 장식용 미리보기로 한정하고 `aria-hidden="true"`로 보조 기술에서 제외한 경우에만 더 작은 글자를 허용한다. 제목·문항 수·카테고리는 카드 바깥 정보 영역에서도 읽을 수 있어야 한다. 입력란은 모바일 확대가 갑자기 발생하지 않도록 16px을 유지한다. 제목의 자간은 -0.015~−0.03em 범위, 본문은 기본값을 사용한다.

유틸리티 클래스: `.mb-display`, `.mb-page-title`, `.mb-section-title`, `.mb-card-title`, `.mb-body`, `.mb-label`, `.mb-caption`, `.mb-reading`.

모바일 페이지·영역·대화상자·주요 버튼의 크기와 행간은 각각 `--mb-mobile-page-{size,line}`, `--mb-mobile-section-{size,line}`, `--mb-mobile-dialog-{size,line}`, `--mb-mobile-action-{size,line}`을 참조한다. 카드 제목을 영역 제목과 같은 크기로 일괄 확대하지 않는다. 입력은 16px, 문제 지문과 긴 문서는 16/28을 유지한다.

## 여백, 크기, 모서리

기본 여백은 **4 / 8 / 12 / 16 / 24 / 32 / 48 / 64px**이다. 변수 이름은 `--mb-space-숫자`다.

| 관계 | 기준 |
| --- | --- |
| 아이콘과 문구 | 8px |
| 라벨과 입력란 | 8px |
| 제목과 설명 | 8~12px |
| 폼 필드 사이 | 16~24px |
| 카드 내부 | 24px, 좁은 화면 16px |
| 카드 사이 | 24px, 좁은 화면 16px |
| 페이지 제목과 콘텐츠 | 데스크톱·모바일 16px |
| 문제지 상위 메뉴 탭 하단선과 페이지 제목 | PC 24px, 모바일은 헤더 안 탭 행과 기존 콘텐츠 상단 간격을 유지 |
| 섹션 사이 | 48px, 좁은 화면 32px |
| 페이지 좌우 여백 | 32px, 태블릿 24px, 모바일 16px |
| 입력·기본 버튼 높이 | 48px |
| 아이콘 버튼의 클릭 영역 | 최소 44 × 44px |
| 폼 폭 | 최대 448px |
| 폼·콘텐츠 카드 모서리 | 16px |
| 기본 입력·버튼 모서리 | 12px |
| 작은 필터·보조 영역 모서리 | 8px |

일반 콘텐츠는 그림자 없이 구분선과 여백으로 나눈다. 문제지 목록은 기존 반응형 그리드를 유지하고 모바일 카드 보기에서는 두 열, 목록 보기에서는 한 열을 제공한다. PRD 카드의 기존 열 수와 전환도 유지한다. 고정 높이로 제목이나 폼 오류를 자르지 않는다.

모바일 독바는 항목 높이 64px, 전체 기본 높이 73px이며 하단 안전 영역은 별도로 더한다. 아이콘/라벨은 18/12px, 380px 이하에서는 16/11px이다. `src/app-header.jsx`와 `src/app-header.css`의 공통 컴포넌트 및 `--mb-mobile-dock-*` 토큰에서 관리한다.

| 순서 | 화면 | 반영 내용 | 완료 판단 |
| --- | --- | --- | --- |

| 4 | 초기 프로필·내 정보 | 이름·회사 폼 간격, 제목과 안내 계층, 저장/취소/로그아웃 통일 | 저장값 유지, 실패 메시지, 헤더 계정 메뉴 확인 |
| 5 | PRD 작업 화면 | 헤더, 제목, 탭, 카드, 입력과 미리보기의 폰트·색 계층 정리 | 생성·편집·미리보기에서 읽기와 기존 기능 확인 |
| 6 | 실제 문제 풀이 | 지문 16/28, 선택지와 버튼 16/24, 메뉴 14/20, 학습 상태 색상 정리 | 풀이·정답·해설·오답·이전/다음·모바일 확인 |

이 문서는 공통 기준과 적용 계획이다. 토큰·문서를 작성한 상태와 모든 화면의 동작 검증을 마친 상태를 구분한다. 실제 완료 범위는 함께 변경되는 화면 파일과 브라우저 검증 결과에 따라 기록한다. 운영 반영은 검증한 버전과 배포 설정을 확인한 뒤 진행한다.

- [ ] 페이지 제목·영역 제목·카드 제목·본문·메타 정보가 같은 역할에 같은 크기를 쓴다.

## 2026-10-24 모바일 현행 기준

- 포켓폴리오의 페이지 제목 24/32/700, 영역 제목 17/24/700, 대화상자·빈 상태 제목 18/26/700, 주요 폼·시트 버튼 16/24/600 계층을 공통 모바일 토큰으로 사용한다. 설명은 13/20으로 정리한다.
- 흰색 화면에 주요 글자 `#191f28`, 설명 `#4e5968`, 보조 글자 `#6b7684`를 사용한다. 보조 면은 `#f2f4f6`, 선택 면은 `#e8f3ff`, 브랜드 강조는 `#3182f6`을 유지한다.
- 좌우 여백 16px과 페이지 제목 다음 콘텐츠 간격 16px을 기준으로 삼는다. 문제지 카드 14/20, PRD 카드 16/24 및 기존 두 열/목록 전환을 유지한다.

- 문제지 목록과 최근 풀이 기록은 `src/paper-preview.jsx`의 동일한 문항지 미리보기 컴포넌트를 쓴다. 풀이 기록에서 순번 다음에 해당 문제지 썸네일을 두고, 사용자 문제지는 저장된 문제 내용을 썸네일에 반영한다.
- 성취도 그래프는 처음 화면에 들어올 때 한 번 그려지고, 운영체제의 모션 줄이기 설정에서는 애니메이션을 생략한다.
- 모바일 문제 생성 입력창은 고정 위치로 이동할 때 620ms 동안 부드럽게 올라와 살짝 가라앉는다. PRD 목록은 스크롤바 거터를 고정하고 대화상자 잠금의 중복 폭 보정을 제거해 프로젝트 선택·폴더 관리 전후 가로 위치가 유지되도록 한다.
- 주요 생성 버튼은 기존 공통 그라데이션을 유지하면서 파랑·보라를 약간 밝게 조정했다. PRD 목록의 랜덤 격려 문구를 없애고 문서 수와 평균 버전 수만 남겼다.
- 모바일 독바의 선택 표시는 84×62px 단색의 옅은 파란 면광으로 보이고, 둥근 곡률은 줄인 형태를 사용한다.
- 변경 확인은 `git diff --check`, 프로덕션 빌드, 생성된 PRD/문제지 번들의 여백·기록 썸네일 규칙 확인으로 진행한다. 실제 iOS/Android 단말 확인은 별도 수행하지 않는다.
