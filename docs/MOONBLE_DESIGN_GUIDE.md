# Moonble 디자인 가이드와 화면별 반영 계획

기준일: 2026-10-14

## 디자인 방향

Moonble의 화면을 차분한 회색 바탕, 흰색 콘텐츠 영역, 명확한 파란색 행동 버튼으로 통일한다. 토스 스타일에서 읽기 쉬운 글자 계층, 충분한 여백, 한 영역에 하나의 주요 행동이라는 원칙을 참고한다. 아래 수치는 Moonble에 적용하기 위해 정한 기준이며 토스의 공식 규격을 뜻하지 않는다.

문제지 목록은 제공된 Figma 홈 캡처의 정보 구조를 참고한다. 왼쪽 탐색, 상단 검색과 필터, 넓은 문서 미리보기, 아래쪽 제목과 설명을 사용한다. 문제지를 선택하면 기존 문제 풀이로 진입한다. 미리보기는 실제 제공되는 문제의 내용으로 구성하고, 임의의 완료율·사용자 수·최근 수정 시각을 표시하지 않는다.

공통 값은 `src/design-system.css`의 `--mb-*` 변수를 단일 기준으로 사용한다. 화면별 CSS에서 같은 역할의 값을 새로 만들지 않는다.

## 웹폰트

- 사용자에게 보이는 한글·영문 UI와 텍스트 기반 Moonble 로고는 **Pretendard**로 통일한다.
- 텍스트 로고는 800을 사용하고, 일반 UI 굵기는 400(본문), 500(메뉴·일반 라벨), 600(폼 라벨·소제목·버튼), 700(페이지 제목)으로 제한한다.
- [Pretendard 공식 웹폰트 안내](https://github.com/orioncactus/pretendard#웹폰트)의 v1.3.9 다이나믹 서브셋을 사용한다. CDN 장애나 로딩 전에는 시스템 글꼴로 본문을 먼저 표시한다.
- 웹폰트 선언만으로 적용 완료를 판단하지 않는다. 대표 한글 문장이 있는 각 화면에서 실제 폰트 로딩과 계산된 `font-family`를 확인한다.
- 폼 컨트롤, SVG의 `text`, 기존 인라인 스타일에도 다른 폰트가 남아 있는지 확인한다. 코드 표시처럼 문법 구분에 고정폭이 필요한 콘텐츠는 별도로 취급한다.

```css
@import url('https://cdn.jsdelivr.net/gh/orioncactus/pretendard@v1.3.9/dist/web/static/pretendard-dynamic-subset.min.css');
font-family: var(--mb-font-sans);
```

## 글자 크기와 계층

표의 px 값은 브라우저 기본 글자 크기가 16px일 때의 기준이다. 구현은 rem을 사용해 사용자의 글자 확대 설정을 따른다.

| 역할 | 데스크톱 크기 / 행간 | 모바일 크기 / 행간 | 굵기 | 적용 위치 |
| --- | --- | --- | --- | --- |
| 특별한 소개 제목 | 32 / 40 | 28 / 36 | 700 | 소개 영역에 한정 |
| 페이지 제목 | 28 / 36 | 24 / 32 | 700 | 로그인, 회원가입, 프로필, PRD, 문제지 목록 |
| 영역 제목 | 22 / 30 | 22 / 30 | 600 | 주요 섹션 |
| 카드 제목 | 18 / 26 | 18 / 26 | 600 | 문제지 이름, PRD 카드·대화상자·편집 툴바 |
| 본문·입력·주요 버튼 | 16 / 24 | 16 / 24 | 400 또는 600 | 안내문, 입력값, 주요 행동 |
| 메뉴·라벨·부가 설명 | 14 / 20 | 14 / 20 | 설명 400, 메뉴·라벨 500, 폼 라벨 600 | 헤더 메뉴, 필드명, 카드 설명 |
| 보조 정보 | 12 / 18 | 12 / 18 | 400 또는 500 | 문항 수, 상태, 날짜 |
| 문제 지문·긴 문서 | 16 / 28 | 16 / 28 | 지문 600, 문서 400 | 지문과 PRD 미리보기 본문 |

사용자에게 읽도록 제공하는 텍스트와 캡션은 최소 12px을 사용한다. 문제지 썸네일 안의 축소 문서는 장식용 미리보기로 한정하고 `aria-hidden="true"`로 보조 기술에서 제외한 경우에만 더 작은 글자를 허용한다. 제목·문항 수·카테고리는 카드 바깥 정보 영역에서도 읽을 수 있어야 한다. 입력란은 모바일 확대가 갑자기 발생하지 않도록 16px을 유지한다. 제목의 자간은 -0.015~−0.03em 범위, 본문은 기본값을 사용한다.

유틸리티 클래스: `.mb-display`, `.mb-page-title`, `.mb-section-title`, `.mb-card-title`, `.mb-body`, `.mb-label`, `.mb-caption`, `.mb-reading`.

## 여백, 크기, 모서리

기본 여백은 **4 / 8 / 12 / 16 / 24 / 32 / 48 / 64px**이다. 변수 이름은 `--mb-space-숫자`다.

| 관계 | 기준 |
| --- | --- |
| 아이콘과 문구 | 8px |
| 라벨과 입력란 | 8px |
| 제목과 설명 | 8~12px |
| 폼 필드 사이 | 16~24px |
| 카드 내부 | 24px, 좁은 화면 16px |
| 카드 사이 | 24px, 좁은 화면 16px |
| 페이지 제목과 콘텐츠 | 32px |
| 섹션 사이 | 48px, 좁은 화면 32px |
| 페이지 좌우 여백 | 32px, 태블릿 24px, 모바일 16px |
| 입력·기본 버튼 높이 | 48px |
| 아이콘 버튼의 클릭 영역 | 최소 44 × 44px |
| 폼 폭 | 최대 448px |
| 폼·콘텐츠 카드 모서리 | 16px |
| 기본 입력·버튼 모서리 | 12px |
| 작은 필터·보조 영역 모서리 | 8px |

일반 카드 그림자는 약하게 적용하고, 구분선과 여백을 먼저 사용한다. 문제지 목록은 가용 너비에 따라 열 수를 줄이고 휴대폰에서는 한 열로 제공한다. 고정 높이로 제목이나 폼 오류를 자르지 않는다.

## 화면별 반영 순서

| 순서 | 화면 | 반영 내용 | 완료 판단 |
| --- | --- | --- | --- |
| 1 | 공통 기반 | Pretendard 로딩, 색·글자·여백 변수, 포커스와 모션 규칙 도입 | 각 진입점에서 공통 CSS가 로드됨 |
| 2 | 문제지 목록 | 왼쪽 탐색과 검색·필터, 실제 지문 미리보기, 제목과 문항 수, 카드 선택 시 풀이 진입 | 검색·필터·빈 결과·모바일 카드와 풀이 연결 확인 |
| 3 | 로그인·회원가입 | 분리된 페이지 유지, 제목·필드·오류·버튼 크기 통일 | 두 경로와 비밀번호 재설정 흐름, 로딩 버튼 확인 |
| 4 | 초기 프로필·내 정보 | 이름·회사 폼 간격, 제목과 안내 계층, 저장/취소/로그아웃 통일 | 저장값 유지, 실패 메시지, 헤더 계정 메뉴 확인 |
| 5 | PRD 작업 화면 | 헤더, 제목, 탭, 카드, 입력과 미리보기의 폰트·색 계층 정리 | 생성·편집·미리보기에서 읽기와 기존 기능 확인 |
| 6 | 실제 문제 풀이 | 지문 16/28, 선택지와 버튼 16/24, 메뉴 14/20, 학습 상태 색상 정리 | 풀이·정답·해설·오답·이전/다음·모바일 확인 |
| 7 | 통합 점검 | 화면 전환, 폰트 로딩, 확대·대비·키보드·빌드 검사 | 아래 수용 기준을 실제 화면에서 확인 |

이 문서는 공통 기준과 적용 계획이다. 토큰·문서를 작성한 상태와 모든 화면의 동작 검증을 마친 상태를 구분한다. 실제 완료 범위는 함께 변경되는 화면 파일과 브라우저 검증 결과에 따라 기록한다. 운영 반영은 검증한 버전과 배포 설정을 확인한 뒤 진행한다.

## 수용 기준

- [x] 로그인·회원가입·프로필·PRD·문제지·풀이 화면에서 Pretendard 웹폰트를 로드한다.
- [ ] 페이지 제목·영역 제목·카드 제목·본문·메타 정보가 같은 역할에 같은 크기를 쓴다.
- [x] 검색, 필터, 카드 선택으로 문제지를 찾고 풀이로 이동할 수 있다.
- [x] 사용 가능한 문제지 내용이 미리보기와 일치하고, 결과가 없을 때 안내와 초기화 경로가 있다.
- [ ] 주요 행동이 한눈에 구분되며 로그인·저장·로그아웃 중에는 스피너와 접근 가능한 상태 이름을 제공한다.
- [ ] 375px, 768px, 1440px 화면에서 의도하지 않은 가로 스크롤·겹침·잘림이 없다.
- [ ] 200% 확대와 긴 한국어 제목에서도 콘텐츠와 버튼에 접근할 수 있다.
- [x] 키보드 탭 이동 시 포커스가 보이고, 카드와 버튼은 키보드로 실행된다.
- [ ] 모션 줄이기 설정에서는 불필요한 회전·이동 효과를 줄인다.
- [ ] 일반 글자·버튼·오류·선택 상태의 색 대비를 확인한다.
- [x] 로그인·프로필 저장·PRD 편집·문제 풀이의 기존 기능을 회귀 확인한다.
- [ ] 빌드와 변경 파일 검토를 마친 후 배포 결과를 확인한다.

## 2026-10-14 적용·검증 기록

- 공통 CSS를 로그인·회원가입·PRD·문제지·풀이 진입점에 연결했다. Paperlogy 로딩을 제거하고 텍스트 로고까지 Pretendard로 맞췄다.
- 문제지 목록에 반응형 사이드바, 문서 썸네일, 검색·분류 필터, 카드/목록 전환과 빈 결과 안내를 적용했다. 제공하는 문제지는 기존 기본·심화·전체 랜덤 3종이다.
- 실제 풀이에서는 글자 크기·여백·선택지·버튼을 조정하고 문제지 목록으로 돌아가는 링크를 추가했다. 기본·심화 첫 진입 시 전체 범위에서 출제되던 초기화 순서도 바로잡았다.
- Chrome에서 Pretendard의 실제 로딩을 확인했다. 문제지 목록의 375/768/1440px 및 프로필·풀이의 375px 화면에서 가로 넘침을 검사했다.
- 테스트용 Supabase 응답으로 로그인/가입 화면 분리, 최초 프로필 입력, 프로필 수정, PRD 생성 및 편집 진입, 로그아웃을 확인했다. 실제 이메일 발송·실계정 가입 검증은 포함하지 않는다.
- 검색·필터·빈 결과 초기화·보기 전환, 3종의 20문항 출제 범위, 채점(19/20), 해설, 오답 재풀이, 다크모드 전환, 키보드 카드 실행을 통과했다. 브라우저 JavaScript 오류는 없었다.
- 남은 수동 점검: 화면 전체의 200% 확대, 긴 사용자 입력의 모든 조합, 모든 상태 색상의 접근성 측정. 위 수용 기준은 확인한 항목만 체크한다.

## 2026-10-19 모바일 적용·검증 기록

- 모바일 공통 기준은 좌우 여백 16px, 입력·주요 버튼 높이 48px, 아이콘형 조작 영역 44×44px 이상, 입력 글자 16px 이상으로 유지한다.
- 소개·로그인·회원가입·약관·개인정보·문제지·성취도·계정·PRD·풀이 화면을 Chrome의 320×568, 360×740, 390×844 환경에서 검사했다. 모든 화면의 문서 폭은 뷰포트와 일치했으며 의도하지 않은 페이지 가로 스크롤은 없었다.
- 모바일 상단에 남아 있던 데스크톱 사이드바 접기 버튼을 숨기고, 풀이 문제 번호·약관 이동·회원가입 동의 상세 링크의 터치 영역을 44px 이상으로 맞췄다.
- 소개 화면 속 제품 데모의 장식용 버튼은 실제 키보드 조작 요소로 인식되지 않도록 정리했다. 전환 애니메이션을 위해 잘림 영역 밖에 대기하는 데모 프레임과 배경 광원은 페이지 너비에 영향을 주지 않는 것을 확인했다.
- 체크박스는 보이는 박스보다 큰 44px 이상의 연결된 `label`을 터치 영역으로 사용한다. 닫힌 대화상자 내부 조작 요소는 화면에 표시될 때 해당 대화상자의 모바일 규칙으로 검증한다.
