# Moonble 브라우저 저장 데이터의 DB 전환 계획

## 권장 순서

문제 공유 기능을 먼저 별도 테이블로 붙이기보다 **문제지와 그룹을 DB의 기준 데이터로 옮긴 뒤 공유를 같은 데이터 모델 위에 추가**하는 순서가 적절합니다. 다만 PRD와 풀이 기록까지 전부 옮긴 후에 공유를 시작할 필요는 없습니다. 문제지·그룹 DB 전환을 첫 번째 단위로 완료하고, 곧바로 그 문제지를 링크로 공유하는 세로 흐름을 검증한 다음 나머지 데이터를 단계적으로 옮깁니다.

공유 링크의 문제 전체를 암호화해 URL에 넣는 방식은 사용하지 않습니다. 링크 자체를 가진 사람이 접근할 수 있는 무작위 공유 토큰을 만들고, DB에는 토큰 해시만 저장합니다. 문제 데이터는 DB의 공유 스냅샷으로 전달하고, 받은 사람은 로그인 없이 읽어 풉니다. 링크를 중지하거나 새로 발급할 수 있어야 합니다. 링크를 받은 사람은 문제와 정답을 볼 수 있으므로 암호화가 접근 제어를 대신하지는 않습니다.

## 현재 저장 위치

| 데이터 | 현재 저장 | 영향 |
| --- | --- | --- |
| 커스텀 문제지·그룹·순서 | 사용자 ID가 포함된 `localStorage` 키 `moonble:user:<id>:custom-banks-v3` | 브라우저/기기 간 동기화가 안 되고, 현재 로컬 값이 유일한 원본 |
| 풀이 기록 | `moonble:user:<id>:history-v3` | 다른 기기에 기록이 이어지지 않음. 최대 200회 저장 |
| PRD·프로젝트 | 사용자 ID가 포함된 `localStorage` 키 `moonble:<id>:prds`, `prd-projects` | 문서·프로젝트의 기기 간 동기화가 안 됨 |
| 계정 프로필 | Supabase `profiles` 및 Auth 메타데이터 | 이미 DB에 존재하고 RLS로 사용자별 접근을 제한 |

현재 Supabase 스키마에는 `profiles`만 있으므로 문제지 공유 링크를 위한 서버 측 문제 저장소도 아직 없습니다.

## 목표 데이터 모델

| 테이블 | 주요 데이터 | 접근 규칙 |
| --- | --- | --- |
| `quiz_groups` | 사용자, 그룹 이름, 정렬 순서, 생성·수정 시각 | 로그인 사용자는 본인 그룹만 CRUD |
| `quiz_banks` | 기존 클라이언트 ID, 사용자, 그룹, 제목, 설명, 문항 JSON, 원본·정렬·생성·수정 시각 | 로그인 사용자는 본인 문제지만 CRUD. 기존 문제지 ID를 그대로 기본 키로 써 이전을 멱등 처리 |
| `quiz_attempts` | 사용자, 문제지·그룹 참조, 풀이 시각, 점수, 정답/전체 수, 문제지 제목 스냅샷, 문항/오답 ID | 로그인 사용자는 본인 기록만 조회·추가·삭제 |
| `quiz_shares` | 문제지 참조, 토큰 해시, 공유 시점 문항 스냅샷, 생성·중지 시각 | 테이블 직접 접근은 차단. 소유자 인증 RPC로 발급/중지하고, 공개 RPC는 활성 토큰의 스냅샷만 반환 |
| `prd_projects` | 사용자, 프로젝트명, 정렬·시각 | 로그인 사용자는 본인 프로젝트만 CRUD |
| `prd_documents` | 사용자, 프로젝트, 제목, 현재 문서 JSON, 생성·수정 시각 | 로그인 사용자는 본인 문서만 CRUD |
| `prd_versions` | 문서, 버전 번호, 저장 시점 문서 JSON, 작성 시각 | 로그인 사용자는 본인 문서 버전만 조회·추가 |

문항은 현재 CSV 모델과 변환 비용을 줄이기 위해 문제지 단위 JSON으로 보존합니다. 단, 저장 크기와 문항 수의 서버 제한을 두고 공유 RPC에서 형식을 검증합니다. 풀이 기록에는 당시 문제지 제목을 스냅샷으로 보존해, 문제지를 나중에 이름 변경·삭제해도 기록이 깨지지 않게 합니다.

## 단계별 작업

### 1. 스키마와 권한

- 기존 `profiles`와 분리된 SQL migration으로 테이블, 인덱스, RLS 정책, RPC를 추가합니다.
- 모든 사용자 데이터 행에 `owner_id`를 두고 `auth.uid()`와 일치할 때만 읽고 쓰도록 검증합니다.
- 비로그인 역할에는 문제지·PRD·풀이 기록 테이블 권한을 주지 않습니다.
- 공유 RPC만 비로그인 호출을 허용하며 토큰 해시 일치, 중지 여부, 스냅샷 크기/형식을 확인합니다.
- 서비스 역할 키는 브라우저에 넣지 않습니다.

### 2. 문제지·그룹 DB 이전과 공유

- `src/custom-bank.js`에 저장 구현을 직접 흩뿌리지 않고, UI가 사용할 저장 어댑터를 둡니다.
- 로그인 후 현재 기기에서 기존 로컬 문제지·그룹을 읽고 DB에 멱등 이전합니다. 기존 ID를 보존하고 서버 행과 로컬 행이 함께 있으면 수정 시각과 ID를 기준으로 병합합니다. 로컬 캐시는 오프라인 접근을 위해 유지합니다.
- 이전 성공 개수와 불일치 항목을 확인한 뒤 DB 읽기/쓰기 경로를 기본으로 전환합니다. 연결 장애 시 로컬 사본을 보존해 복구할 수 있게 합니다.
- 문제지 CRUD·그룹 CRUD·정렬·풀이 진입이 이전 후에도 동작하는지 확인합니다.
- 이 DB 문제지에 공유 링크 발급·복사·중지, 비로그인 풀이를 붙입니다. 공유 스냅샷은 링크 생성 시점 내용을 보존합니다.
- 사용자가 아직 방문하지 않은 다른 브라우저의 로컬 데이터는 자동으로 가져올 수 없으므로, 그 기기에서 로그인해 같은 이전 절차를 수행해야 합니다.

### 3. 풀이 기록 이전

- 현재 최대 200개의 기록을 필드 단위로 검증해 DB로 옮깁니다.
- 저장 후 합계와 최신 기록 날짜를 비교하고, 중복 실행을 막기 위한 기존 기록 ID 또는 안정적인 지문을 둡니다.
- 성취도 필터·차트·CSV/PDF 출력이 DB 결과를 사용하도록 연결합니다.
- 비로그인 공유 풀이 결과는 계정 성취도에 자동 귀속하지 않습니다. 게스트 결과 보존이 필요하면 별도 동의와 만료 정책을 설계합니다.

### 4. PRD·프로젝트 이전

- 현재 문서/프로젝트 JSON 구조를 그대로 보존해 사용자별 DB 행으로 이전합니다.
- 현재 저장 내용과 버전 기록의 의미를 확인한 다음 `prd_versions` 생성 시점을 맞춥니다.
- 생성·편집·삭제·프로젝트 이동·버전 복구·내보내기를 DB 기준으로 전환합니다.

### 5. 안정화와 로컬 정리

- Preview에서 계정 두 개, 서로 다른 브라우저, 모바일 화면, 네트워크 단절, 새로고침, 재로그인, 삭제/복구를 확인합니다.
- SQL 권한 점검에서 계정 A가 계정 B의 데이터 조회·변경을 못 하는지 검사합니다.
- 이전이 확인되기 전에는 로컬 사본을 지우지 않습니다. 안정화 후에도 사용자 확인 없이 일괄 삭제하지 않습니다.
- 운영 반영은 스키마 적용, Preview 검증, 코드 배포 순서로 진행하고, 이전 상태로 되돌릴 경로를 남깁니다.

## 완료 조건

- 같은 계정으로 다른 기기에 로그인해 문제지·그룹·풀이 기록·PRD가 이어집니다.
- 한 계정에서 다른 계정의 데이터를 조회·수정할 수 없습니다.
- 기존 로컬 데이터는 중복 없이 재실행 가능한 방식으로 DB에 이전됩니다.
- 공유 링크는 URL에 문제 본문이나 정답을 담지 않고, 받는 사람은 로그인 없이 문제를 풀 수 있습니다.
- 소유자가 링크를 중지한 뒤에는 같은 링크로 더 이상 풀 수 없습니다.
- 기존 풀이·기록·문제지 편집·PRD UI와 라우팅은 시각적 변경 없이 동작합니다.

## 현재 권장 범위

첫 번째 구현 단위는 **문제지/그룹 DB 저장 어댑터와 멱등 로컬 이전 → 문제지 CRUD 회귀 확인 → 공유 링크 발급/비로그인 풀이**입니다. 풀이 기록과 PRD는 데이터 구조를 먼저 확정하되, 첫 단위가 안정화된 뒤 별도 migration으로 진행합니다. DB SQL을 Supabase에 적용하고 계정 간 권한을 실측하기 전에는 이 기능을 운영 완료로 간주하지 않습니다.
